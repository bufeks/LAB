# 下書きルーティン

Claude Code の Routine（定期実行）で、毎週の下書きづくりを自動にしています。
**Substack への投稿はしません。** 下書きを Google ドライブに置き、Gmail で知らせるところまでです。

## 1. 設定

| 項目 | 値 |
| --- | --- |
| 名前 | Uraroji weekly draft |
| 実行 | 毎週月曜 08:52 JST（`CRON_TZ=Asia/Tokyo 52 8 * * 1`） |
| 方式 | 実行ごとに新しいセッションを作る |
| 使うコネクタ | Google Drive、Gmail |
| 読むもの | このリポジトリ（`bufeks/lab`）の `uraroji/` |
| 出力 | Google ドライブ「Uraroji Drafts」に Google ドキュメント1つ。通知メール1通（自分宛て） |

変更や停止は claude.ai の Routines 画面から。またはこのセッションに頼めば直せます。

## 2. ルーティンに渡している指示文

この文面を変えたときは、Routine 側の指示文も同じ内容に更新してください（セッションに「指示文を更新して」と頼めば直せます）。リポジトリは公開されるので、ここではメールアドレスを伏せています。Routine 側には実際のアドレスが入っています。

```text
あなたは英語ニュースレター「Uraroji」(Substack) の編集アシスタントです。今週の下書きを1本作ります。Substack への投稿や、自分宛て以外へのメール送信は絶対にしないでください。

■ 1. 資料を読む
GitHub リポジトリ bufeks/lab の uraroji/ フォルダを読みます。作業ディレクトリにあればそれを、なければ GitHub のツールでデフォルトブランチから読みます（デフォルトブランチに uraroji/ がなければ claude/uraroji-newsletter ブランチから）。必ず読むもの：
- uraroji/brand/voice.md（文体・表記・事実・著作権のルール）
- uraroji/templates/deep-cut.md（毎週号の型）、uraroji/templates/long-read.md（Long Read の型）、uraroji/templates/social.md（SNS の型）
- uraroji/editorial/calendar.md（編集カレンダー）

■ 2. 今回の号を決める
Google ドライブで「Uraroji Drafts」フォルダを探します（なければ作ります）。中のドキュメント名は「Uraroji #NN — ...」の形です。calendar.md の表を上から見て、そのフォルダにまだ「Uraroji #NN」のドキュメントがない最初の号を今回の号にします。表の号がすべて済んでいたら、下書きは作らず、「カレンダーの補充が必要です」と通知メールだけ送って終わります。

■ 3. 調べる
Web で調べ、次の事実を出典つきで確かめます：作者・監督の名前の表記、発表年と媒体、あらすじの要点、日本での評価と影響、英訳・英語字幕版の有無（出版社・収録巻・配信先・入手方法）。出典で確かめられないことは本文に書くか書かないかを決め、書く場合は [要確認] を付けます。推測で事実を作らないでください。

■ 4. 下書きを書く
種別が Deep Cut または Context なら deep-cut.md の型、Long Read なら long-read.md の型で、英語の本文を書きます。voice.md の声と表記に従います。「The maker's eye」と「A local's note」は、書き手（日本在住の美大卒の現役クリエイター）本人が書く欄なので、本文を埋めずに次の形でヒントだけ置きます：
[YOUR TAKE: 書くべきことのヒントを日本語で2〜3行。例：どのコマ・場面を取り上げると効くか、どんな個人的な記憶があると強いか]
AI っぽい決まり文句（delve, tapestry, testament, in the realm of など）は使いません。

■ 5. Google ドキュメントを作る
「Uraroji Drafts」フォルダに、名前「Uraroji #NN — <作品名> — <配信日>」で Google ドキュメントを作ります。中身の順番：
1) 作業メモ（日本語）：この号のねらい、あなたがやること（[要確認] の数、[YOUR TAKE] の数、画像の候補）
2) 件名案3つ（型1〜3）、サブタイトル、SEO 用の検索タイトルと説明文（155字以内）
3) 英語本文
4) 事実の出典一覧（URL）
5) 画像の候補：作品のどの画像を1〜3点使うと論評に効くか、出典の書き方、自作の図解のアイデア（画像そのものは探して貼らない）
6) SNS の文面：Substack Notes 2本、X/Bluesky のスレッド6投稿、Instagram カルーセル5枚分の文言
7) 日本語の要約（300字）：書き手が内容をすぐ確かめられるように

■ 6. 通知する
Gmail で <あなたのメールアドレス> 宛てに1通だけ送ります。件名「[Uraroji] #NN 下書きができました — <作品名>（<配信日>配信）」。本文は日本語で：ドキュメントのリンク、[要確認] の数と中身、[YOUR TAKE] の数、予約の期限（配信日の前日の水曜まで）、気になった点。

■ 7. 最後に
作ったドキュメントの名前とリンクを、このセッションの最後に短く報告して終わります。リポジトリには変更を加えません。
```

## 3. 手動で追加実行する（ストックを増やしたいとき）

- このセッション、または新しいセッションで「Uraroji の下書きルーティンを今すぐ実行して」と頼む
- claude.ai の Routines 画面から「Run now」
- 1回の実行で1本できる。カレンダーの次の号が自動で選ばれる

## 4. うまくいかないとき

| 症状 | 見るところ |
| --- | --- |
| メールが来ない | Routines 画面で直近の実行が失敗していないか。Gmail コネクタが接続されているか |
| 同じ号がまた作られる | ドライブのドキュメント名が「Uraroji #NN — ...」の形から変わっていないか（名前を変えると別の号と判断できない） |
| 予定と違う号ができる | `editorial/calendar.md` の表の順番。変更がデフォルトブランチにマージされているか |
| 事実の誤りが多い | voice.md §3 を強める。指示文の §3 に確かめる項目を足す |
| 文章が自分の声と違う | voice.md §1 に「自分ならこう書く」例文を3つ足すと効く |
